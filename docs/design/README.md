# 设计稿交付约定

设计稿由成员 B 按技术文档第 4 章的前端约束和 2.1 功能表制作，成员 A 审阅后落地为设计 token 与公共组件（ADR-008）。本文规定**设计稿怎么交付**，这样 A 和两位成员的 AI 助手都能直接从仓库里读到。

## 1. 交付方式：提 PR，导出成图片放进仓库
- 设计稿**通过 PR 提交**到 `docs/design/`，不放在聊天、网盘或只有链接的设计工具里。AI 助手读不到链接，只能读仓库里的文件。
- 分支名：`feat/b-<ticket>-design-<name>`，PR 标题以 `design:` 开头。
- 设计工具（如 Figma）的原文件**不入库**；可以在说明里附链接作为参考，但链接**不能代替**导出的图片。
- 一个 PR 交付一个页面或一个流程，不要把所有页面攒成一个大 PR。

## 2. 目录与命名
```
docs/design/
  README.md                         本文件
  <page>/                           例如 generate-workbench、result-page、knowledge-review
    spec.md                         一页说明（见第 3 节）
    01-<page>-empty.png             状态图，序号加页面名加状态
    02-<page>-loading.png
    03-<page>-success.png
    ...
```
- 状态名用英文小写：`empty`、`loading`、`success`、`error`、`forbidden`、`constraint-failed`、`needs-review`、`ready-to-copy` 等。
- **每张 PNG 不超过 500 KB**（用 TinyPNG、pngquant 等压缩；仓库的 `pre-commit` 对大文件有限制）。宽度建议 1440 px，至少 1280 px。
- 示例里的品牌与商品资料用自编内容，**不要使用客户品牌手册的原文或截图**（ADR-007）。

## 3. 每个页面一页 `spec.md`
用下面的模板，写完整比写漂亮更重要：

```markdown
# <页面名>

- 对应需求：F4、F5……（技术文档 2.1）
- 路由：/generate
- 角色与权限：editor、admin 可见；editor 看不到某按钮则写明
- 负责人：B（页面）；A 审阅（token、公共组件）

## 状态清单
| 状态 | 图片 | 说明 |
|---|---|---|
| 空 | 01-…-empty.png | |
| 加载中 | | 用 progress.stage 显示进度 |
| 成功 | | |
| 错误 | | 显示 request_id（FC-07） |
| 403 | | |

## 区域与字段
每个区域列出：显示什么、数据来自哪个接口字段（以 docs/API_CONTRACT.md 为准）、文案来源。
下拉与选项必须来自接口（例如 GET /scenarios），不要在设计里写死。

## 交互
点击、复制、编辑、重试、断线恢复等行为，一条一条写。

## 用到的组件与 token
列出用到的公共组件；颜色、字号、间距只写 token 名，不写色值（FC-04）。

## 与契约或约束不一致的地方
设计需要但契约里还没有的字段、状态、接口，列在这里；A 评估后走契约变更 PR（见 AI_TEAM_GUIDE）。
```

## 4. B 负责的页面清单（必须覆盖）
- 生成工作台：场景与风格、brief、当次资料、必含词与禁用词（高级选项）、提交与进度。
- 结果页：标题候选、正文、标签、封面文案候选；**证据面板**（来源级别、版本、状态、“系统判定支持”旁的“非事实保证”提示）；**风险面板**（规则出处、版本、严重度、替换建议）。
- 编辑与复检、版本对比、确认、导出：**三个复制按钮**（复制标题、复制正文、复制标签，ADR-005），标签显示“已选 N / 10”并提示“粘贴不会变成话题”；标题与正文的字数提示按 ADR-004。
- 任务与版本历史；评测集、评测运行与报告；合规规则查看。
- 每个页面都要有：加载、空、错误（显示 `request_id`）、403 四种状态，以及状态标签映射（技术文档 4.4）。
- 全局约束见技术文档 4.2：桌面优先（≥1280 px）、不放未实现功能的入口、不使用“合规通过”“已验证事实”“法务批准”“保证合规”。

## 5. 谁读、怎么读
- **A**：审阅后提取 design token（`index.css`）和公共组件；在 PR 评论里确认或提出修改。设计稿在 A 确认后才作为视觉基线（ADR-008）。
- **AI 助手**：图只当**视觉参考**；字段、选项、文案以契约、文案模块和接口为准，不得凭图编造选项或默认值。看到图与契约冲突，先列出来问人，不要自己选一边。
- 没有强制批准（ADR-009），所以设计稿 PR 合并前，B 要在评论里 @ A 并等到确认。

## 6. 设计稿 PR 自检
- [ ] 每个页面都有 `spec.md`，状态清单完整
- [ ] 所有 PNG ≤ 500 KB，命名符合约定
- [ ] 没有客户原文、截图、密钥
- [ ] 字段与契约一致；不一致的已写进“与契约不一致的地方”
- [ ] 没有违禁措辞，没有未实现功能的入口
- [ ] 已 @ A 并等到确认
