## 区域与字段
**版本列表**（`GET /brands/{brand_id}/voice-profile/versions`）：版本号 `version`、创建时间 `created_at`、“生效中”（`is_active`）；非生效版本在 admin 视角有“设为生效”。
**所选版本详情**（`GET /brands/{brand_id}/voice-profile` 取生效版本；其他版本取自版本列表）：品牌人设 `persona`、语气关键词 `tone_keywords`、优先词 `preferred_words`、禁用词 `forbidden_words`、参考样例 `sample_refs`。
**新建版本抽屉**（`POST /brands/{brand_id}/voice-profile/versions`，仅 admin）：同上五个字段；保存后生成新版本，`is_active=false`，**不会自动生效**，需要在版本列表里点“设为生效”。
**设为生效**（`POST …/versions/{version}/activate`）：确认弹窗说明“激活后旧版本保留，每个品牌只有一个生效版本”。
**追溯提示**：页面顶部说明“品牌档案会随任务记录 `voice_version`，便于追溯”（契约 NFR1、任务字段 `voice_version`）。

## 交互
- 旧版本只读，任何修改都创建新版本，不编辑旧版本。
- 保存成功后抽屉关闭、版本列表刷新、新版本出现在列表里（未生效）。
- 禁用词下方提示“生成后将检查是否包含这些词”，与生成工作台里必含词的提示口径一致。
- 不画“AI 起草”按钮：契约把 `drafts` 列为 P1 且“尚未实现”，并要求人工确认，本页不放未实现功能的入口（技术文档 4.2）。
- 只有 401 才退出登录。

## 用到的组件与 token
标签输入与标签（语气关键词、优先词、禁用词；禁用词用错误色调的中性标签）、右侧抽屉与遮罩、状态徽标（生效中、已停用的历史版本）、确认弹窗、错误条加请求编号、骨架、空状态；沿用 design-tokens 与 common-components，没有新增 token。
