## 状态清单
列表：加载中（骨架）、空、筛选后为空、请求失败（带请求编号和重试）、403、正常、进行中的行、失败的行、分页边界。
详情：加载中、404、只有一个版本、正在生成或检查、分支版本、正常。
对比：未选满两个版本、选了同一个版本、内容完全相同、版本详情加载失败（只影响摘要块）、正常。
全部见 05；对比的两个正常态见 03、04。

## 区域与字段
**任务列表**（`GET /tasks?brand_id=&status=&sort=&page=&page_size=`）
- `brand_id` 来自顶栏当前品牌；`status` 取 `flow_status` 的 8 个值；`sort` 为 `-created_at`（默认，“最新创建在前”）或 `created_at`；`page_size` 默认 20、最大 100。
- 每行：`scenario_name · product_name`、`brief`（单行截断）、`flow_status` 徽标（文案沿用技术文档表 4-4）、`created_at`。`generating / checking` 时在徽标下用 `progress.stage` 显示阶段名（检索资料、生成中、核对依据、风险提示、改写中）；`last_error` 有值时下面显示一行红字。
- 行操作：`queued` 显示“继续”，进行中显示“查看进度”（回到 `/generate?task=<id>`），其余显示“查看结果”（打开 `latest_version_id`）和“版本历史”。**“版本历史” = `/tasks/:taskId`，即任务详情页里的版本列表，不是另一个页面。**
- 分页信息用响应的 `total / page / page_size`。

**任务详情**（`GET /tasks/{id}`、`GET /tasks/{id}/materials`、`GET /tasks/{id}/versions`）
- 任务信息：场景、商品、brief、必含词、风格、`flow_status`、创建时间。任务资料：`filename`、`char_count`、`excerpt`。
- 版本列表：`version_no`、`origin`、`parent_version_id`（显示为“基于 vN”）、`flow_status`、首个标题候选预览、`created_at`、`model`、`confirmed_at`（有则显示确认时间，**不显示确认人**）。最新版本标“最新”。每行有复选框和“打开”。
- “对比所选版本”：恰好勾选 2 个才可点；少于 2 个时禁用并写“请勾选 2 个版本”。

**版本对比**（只用 `GET /tasks/{id}/versions` 里已有的字段；没有对比接口）
- 左右各一个版本选择器、交换按钮、“只看有差异的项”开关（默认开）。
- 两张元信息卡：origin、`parent_version_id`、`flow_status`、`created_at`、`model`（为空显示“无（人工编辑）”）。
- 差异概览：标题候选、正文、标签、封面文案各“相同 / 有差异”。
- 标题候选：按文字集合比较；每条显示加权长度（ADR-004，ASCII 可打印字符 0.5、其余 1，≤20）。
- 正文：先按行比较，行内再按字比较。删除用红底删除线加“－”，新增用浅蓝底加粗加“＋”，有变化的行左侧标“±”，**不只靠颜色**。
- 标签、封面文案：同样标新增和删除，标签显示“已选 n / 10”。
- 字数：前端按 ADR-004 算——标题（第 1 个）加权长度、正文含标签的 UTF-16 码元（每个标签计 1+名字+1，emoji 在正文里计 2）、标签数。
- 证据与风险摘要：每个版本 2 次请求。证据统计 `evidence_summary` 取自 `GET /generation-versions/{id}`（版本详情；版本列表里没有这个字段，不从列表取）；风险提示条数和“未处理的必须修改”数取自 `GET /generation-versions/{id}/compliance`（返回 `items` 和 `unresolved_block`；版本详情里没有风险提示）。任一请求失败只影响这一块，其余字段比较照常。
- 不画“更好 / 更差”的评价，也不对差异下合规结论。

## 交互
- 列表点一行进详情；筛选和排序改变后回到第 1 页，清除筛选恢复默认。
- 详情勾选两个版本后进入对比，左边是较早的版本、右边是较新的版本（默认值，用户可交换）。
- 对比页的选择器列出该任务的全部版本，选同一个版本时提示“请选择两个不同的版本”，不显示差异。
- 版本之间用“基于 vN”表示父子关系；从旧版本再编辑会出现分支，不画成单线。
- `generating`、`checking` 的任务，列表和详情每 3 秒轮询一次，进入结束态就停；超过 5 分钟仍未结束，降到每 10 秒（A 已同意）。
- 结果页页头加“版本对比”和“版本历史”两个入口，本页落地后才加（#45 已去掉占位）；“版本对比”仅在任务有 ≥2 个版本时可点。

## 用到的组件
状态徽标（`flow_status` 全部取自 common-components 与 design-tokens）、错误条、请求编号复制、403 与 404 提示、骨架、空状态、分页、复选框、下拉选择、标签。差异标记（红色删除线、浅蓝加粗）是本页新增的两个样式，只在对比页使用，颜色取 token：删除用 error 系，新增用 system_supported 的浅蓝；落地时若要进公共组件，另提小 PR。输入框边框用 `input-border`。

## 已决定
- 三条路由 `/tasks`、`/tasks/:taskId`、`/tasks/:taskId/compare?left=&right=`（A 已同意，前端按此建路由）。
- `origin = rewritten` 只写“改写”，不区分自动改写与人工局部重写（后端目前区分不了，不改后端；A 已同意）。
- origin 的中文叫法：系统生成、人工编辑、改写（A 已同意）。
- 轮询：见“交互”（A 已同意）。
- 对比页每个版本 2 次请求（详情 + 风险），A 认为可以接受。
- 版本对比由前端比较，不加接口（A 已确认）。
- 不显示“确认人”，只显示 `confirmed_at`（A 已确认）。
- 任务没有名称字段，标题用“场景名 · 商品名”拼出（契约没有 `name`）。
- 没有“创建人”列（契约列表项没有该字段）。
