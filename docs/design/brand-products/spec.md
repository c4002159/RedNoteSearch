## 区域与字段（接口以 `docs/API_CONTRACT.md` 第 3 节为准）
**列表**（`GET /brands/{brand_id}/products?status=active|archived&page=`，响应 `{items,total,page,page_size}`，`page_size` 默认 20、最大 100）
- 页头：标题、说明、主按钮“新增商品”（仅 admin）、分段切换“在用 / 已归档”（对应 `status`，默认 `active`）。
- 表格列：商品名称 `name`、产品线 `product_line`、类目 `category`、卖点（有来源条数 / 总条数，由 `selling_points[].evidence_status` 统计）、状态 `status`、操作（编辑、归档，仅 admin 且仅在用）。
- 底部：每页条数、总数、翻页。

**编辑抽屉**（`POST /brands/{brand_id}/products`、`PATCH /products/{product_id}`，仅 admin）
- 商品名称（必填）、产品线、类目（`category` 的取值以接口为准，设计里的中文名是示例）。
- 香调 `notes.top / middle / base`：三组标签输入。
- 卖点列表 `selling_points[]`：每条有 `text`；`evidence_status = linked` 显示绿色“有来源”并写出资料名、版本、片段（来自 `source_document_id`、`source_chunk_id`）；`draft` 显示灰色“草稿·无来源”，并提示“无来源的卖点只保存为草稿，不能作为证据”。“关联已审核资料来源”只能选本品牌已审核且为当前版本的资料。
- 禁用宣称 `restricted_claims`：标签输入；提示“合规检查会读取这些词”。
- 底部：取消、保存。

## 交互
- 保存成功后关闭抽屉并重新请求列表；保存失败显示错误条加 `request_id`。
- 关联的资料来源不是“已审核且为当前版本”，或分块不属于该资料：接口返回 409，抽屉里显示错误条（文案按 `error.message`）。
- 归档：确认弹窗（带原因输入不需要，接口没有 `reason`）；归档后从“在用”消失，已被历史任务引用的商品保留。
- 商品不存在与无权限都是 403（契约实现约定），不区分。
- 只有 401 才退出登录。

## 用到的组件与 token
状态徽标（有来源、草稿、在用、已归档）、表格与分页、分段切换、右侧抽屉与遮罩、标签输入、输入框、下拉、错误条加请求编号、骨架、空状态；沿用 design-tokens 与 common-components，没有新增 token（FC-04）。

## 未验证
- 类目 `category` 的取值：契约商品示例里只有 `perfume`，品牌的 `category` 有五个取值；商品类目是否同样用这五个，需要 A 确认。设计里的“香水 / 护肤 / 彩妆 / 家居香氛 / 其他”按品牌的取值画。
- 卖点来源的显示（资料名、版本、片段）需要由资料 id 解析出名称；契约响应里只有 id，是否返回资料标题，需要 A 确认。
- “卖点：有来源 / 共”由前端对 `selling_points[].evidence_status` 计数；契约没有单独的计数字段。
- 编辑者是否能打开编辑抽屉的只读版本，契约没写；图只画了管理员。
- 商品编码、关联类目这类字段没有画，契约没有。
- 没有调用任何接口；版面是我自己看的，没有别人看过。
