- 对应需求：技术文档表 4-3 的“知识库”三页（P0）；契约第 4 节（知识资料）与 1.5（上传限制）；表 4-4 资料状态标签
- 路由（建议，技术文档表 4-3）：`/knowledge`（资料列表与上传）、`/knowledge/review`（待审队列与审核）、`/knowledge/:id`（资料详情）。`:id` 是某个版本行的 id（契约实现约定）

- 示例资料全部自编，文件名带“（演示）”，不含客户资料，不放品牌手册内容。

## 角色与权限
| 操作 | 编辑者 | 品牌管理员 |
|---|---|---|
| 查看列表、详情（元数据、版本链、审核记录） | 是 | 是 |
| 提交待审资料（含提交新版本） | 是 | 是 |
| 直接入库、上传新版本（直接成为当前版本） | 否 | 是 |
| 待审队列与审核 | 不渲染 | 是 |
| 分块预览 | 不渲染 | 是 |
| 重建索引、停用 | 不渲染 | 是 |

没有权限的入口不渲染（不是置灰）；权限以后端 403 为准（FC-08）。“待审队列”导航项旁显示待审数量（技术文档 4.1：徽标只用于有真实含义的标记）。

## 状态与枚举
- 资料状态（契约 4 节）：`pending_review` 待审核（橙）、`approved` 已入库（绿）、`rejected` 已驳回（红）、`deactivated` 已停用（灰），与表 4-4 一致。
- 索引状态 `index_status`：`ready` 可检索、`pending` 待建立索引、`failed` 索引失败。它是**另一个维度**，只在“已入库”的资料上显示，不和审核状态混在一个标签里。
- **不画 `queued` 和“解析中”**：契约的资料状态里没有它们，上传是同步的（见“与契约不一致”）。

## 状态清单
列表：加载中、空、筛选后为空、加载失败、正常。
上传 / 提交窗口：未选文件、已选文件、处理中、各类错误。
审核窗口：通过、驳回、驳回理由为空、503、409。
详情：加载中（骨架）、404、已入库、待审核、已驳回、已停用、已入库但索引失败、已入库但索引待建立。
停用窗口：正常、处理中、409。

## 区域与字段
**资料列表**（`GET /brands/{brand_id}/knowledge-documents?status=&doc_type=&page=`）
- 页头主按钮：品牌管理员“上传资料”（直接入库），编辑者“提交待审”。
- 筛选：状态（4 个 `status`）、类型（6 个 `doc_type`）、“清除筛选”。
- 列表的“标题”列**只显示标题，不带文件扩展名**（如“示例成分说明（演示）”，不写“….pdf”）；原文件名只在详情的元数据里显示为“原文件名”（2026-11-02 订正，以实现为准；图 01 把标题和扩展名画在一起，以本文为准）。
- 表格列：标题、类型、状态、索引（仅已入库显示，其他显示“—”）、提交人、提交时间；点一行进入详情。**版本不单独成列**：写在标题下一行，如“v1 · 当前版本”，历史版本写“v1 · 历史版本”（2026-11-02 订正，以实现为准；图 01 里的“版本”列以本文为准）。
- 页头副文案写明检索规则：只有“已入库”且“可检索”的当前版本才会被新任务用于生成和核对依据。

**上传 / 提交窗口**
- 管理员：`POST /brands/{brand_id}/knowledge-documents`，字段 `file`、`title`、`doc_type`；成功后直接是已入库、可检索，并写审计。提示“解析、分块、建立索引都成功后立即成为当前版本”。
- 编辑者：`POST /brands/{brand_id}/knowledge-submissions`，字段 `file`、`title`、`doc_type`，可选 `supersedes_document_id`（从某份资料的详情里“提交新版本”进入时带上）；提示“通过前不会被用于生成”。
- 文件限制（契约 1.5）：PDF、DOCX ≤50 MB；MD、TXT、CSV ≤5 MB；PDF 需有文字，不做 OCR。
- 处理中：按钮显示“正在处理…”并禁用；成功或失败都在同一次请求里返回，没有中间阶段。

**待审队列**（列表接口 `status=pending_review`，仅管理员）：标题、类型、版本、与已有资料的关系（新资料或更新）、提交人、提交时间、“审核”。副文案：通过前待审资料不会被用于生成；若它是新版本，通过前仍使用旧的当前版本。

**审核窗口**（`POST /knowledge-documents/{id}/reviews`，体 `{action: approve|reject, reason}`）
- 顶部资料摘要；分块预览（`GET …/chunks`，前几块）用来核对解析结果。
- 通过：备注选填。说明：通过后才为它建立索引，建好后才可检索；若替代旧版本，旧版本不再是当前版本。
- 驳回：**理由必填**（契约），为空时字段下显示“驳回必须填写理由”，不发请求。
- 通过时嵌入模型不可用：503 `MODEL_UNAVAILABLE`，资料仍是“待审核”，可重试。资料已被别人处理：409 `INVALID_STATE`，刷新列表。

**资料详情**（`GET /knowledge-documents/{id}`）
- 页头：标题、类型、版本、提交人、提交时间；状态与索引状态标签。操作（管理员）：重建索引（仅已入库）、上传新版本、停用（仅已入库）；编辑者：提交新版本（待审）。
- 元数据卡、分块预览（仅管理员，翻页，`GET …/chunks?page=`）、版本链（当前版本标“当前版本”，其余标“历史版本”）、审核记录（只增不改：操作、审核人姓名 `actor_name`、时间、理由；用户已不存在显示“未知用户”）。
- 索引失败时顶部红色提示，失败期间不可检索，可“重建索引”；已停用时提示“新任务不会再检索它；已有任务保留当时引用的快照”。

**停用窗口**（`POST /knowledge-documents/{id}/deactivate`）：显示资料摘要；“原因”输入框，**界面画成选填**（接口 `reason` 可选，≤500 字，写入这次停用的审核记录和审计）。说明：新任务不会再检索它，已有任务保留引用快照，不会物理删除。A 允许界面做成必填，只需去掉“选填”并禁用提交按钮，其余不变。

## 交互
- 上传、提交、审核、停用、重建索引都是居中弹窗或按钮操作，主按钮与次按钮（技术文档 4.1）。
- 审核或停用成功后，列表和详情重新请求；状态不符（409）时刷新并提示。
- 只有 401 才退出登录；403、404 沿用公共组件（404 不区分不存在与无权）。

## 用到的组件
状态徽标（资料状态、索引状态）、表格与分页、筛选下拉、居中弹窗、文件选择区、输入框（`input-border`）、单选、错误条加请求编号复制、骨架、空状态。沿用 design-tokens 与 common-components；本页没有新增 token。“历史版本”“待建立索引”两个标签用灰色中性标签，不新增颜色。

## 与契约不一致的地方
- 契约 4 节的实现约定里写“单文件 ≤ 10 MB（超过 413）”，与 1.5 节的“PDF、DOCX 50 MB，MD、TXT、CSV 5 MB，超限 422 `FILE_TOO_LARGE`”矛盾；图按 1.5（A 的实现记录为准）。以契约 1.5 为准，A 会更正契约 4 节的旧说法。
- 需求里提到的 `queued` 状态：契约的资料状态只有 4 个，没有 `queued`，所以没有画。
