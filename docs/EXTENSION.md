# 笔记成绩助手（浏览器插件）

作用：运营把文案发到小红书后，回来登记成绩时少敲三个数字。插件读取**你已经打开的笔记页上显示的**点赞、收藏、评论数，你核对后点“发送”，数字就记到系统里对应的“已确认文案”上。

## 它做什么，不做什么
- 只在你点开插件并点“读取当前页面”时运行一次；没有后台脚本，没有定时任务，不会自己打开任何页面。
- 只读页面上已经显示的三个数字和“共 N 条评论”；不读评论内容、用户、账号、Cookie。
- 不请求小红书的任何接口，不翻页，不模拟登录。
- 数字发到哪里由你决定：只发到你在“连接设置”里填的系统地址，并且需要你点“发送”。
- 发送的内容：三个数字、是否近似、读取时间，以及笔记页地址中的路径（不含查询串，因为它可能带令牌）。系统也不保存这个地址。
- 权限：`activeTab`（只对你点开插件的那个标签页）、`scripting`（读取该页面）、`storage`（保存系统地址和密钥）。系统地址的访问权限是你在“保存并授权”时才申请的，只申请你填的那一个地址。

## 安装（开发者模式）
1. 打开 `chrome://extensions`，打开右上角“开发者模式”。
2. 点“加载已解压的扩展程序”，选仓库里的 `extensions/results-helper` 文件夹。
3. 在系统里由品牌管理员生成插件密钥（`POST /brands/{brand_id}/extension-keys`，密钥只显示一次，请立刻复制）。**目前没有对应的界面，只能用接口生成**，界面等设计稿。
4. 点插件图标，展开“连接设置”：把系统密钥页上显示的**连接配置**整串粘贴到第一栏，点“使用配置并授权”，地址和密钥一次填好。没有配置串时，在下面两栏手动填系统地址（例如 `http://localhost:8011`）和密钥，点“保存并授权”。
   - 连接配置里包含密钥，和密钥一样只在生成时显示，不要发到聊天、PR 或 Issue。
   - 格式：`rnk1.` 加 base64url 编码的 JSON `{"s":"系统地址","k":"rnk_…"}`。由系统的密钥页（前端）用当前访问的接口地址和刚生成的密钥拼出，后端不参与、也不保存。

## 每次使用
1. 在系统里打开这篇“已确认文案”，保存它的**帖子网址**（插件靠网址里的笔记 id 找到它；`xhslink.com` 短链接取不到 id，这种笔记要手填成绩）。
2. 在 Chrome 桌面版打开这篇笔记，点插件的“读取当前页面”。
3. 核对三个数字。页面显示“2.1万”这类缩写时，数字是近似值，会自动勾选“近似”。
4. 点“发送到系统”。

## 会出错的地方
- 评论数会和评论区的“共 N 条评论”交叉核对：不一致时不会通过，要你手动改；评论区没出现总数时只提示“未核对”。
- 只读具体的笔记页（网址里有 24 位笔记编号）。在首页、搜索页、个人页打开插件，会提示“请先打开一篇具体的笔记”，不会读取，避免把信息流里别的笔记的数字当成这篇的。从信息流点开的笔记浮层，背景里还有信息流卡片的点赞数：插件以收藏、评论数所在的那一块为准取点赞数；页面分不清是哪一篇时三项都不读，提示在页面上有多处数字，请关闭浮层、直接打开这篇笔记再读（选择器范围待 B 在真实 Chrome 里复测确认）。
- 页面结构变了读不到时，会明确提示读不到什么，不会猜；你手填即可。
- 这些选择器（`.like-wrapper .count`、`.collect-wrapper .count`、`.chat-wrapper .count`、`.total`）来自对桌面版 Chrome 一篇笔记页的观察（Issue #162），**只在该页面结构的副本上验证过，没有在线上页面自动验证**。
- 密钥保存在本浏览器的本地存储里，没有加密。丢了或换了电脑，请在系统里作废（`DELETE /brands/{brand_id}/extension-keys/{id}`）再生成新的。
- 同一篇笔记一小时内最多接收 12 条来自插件的读数。

## 在自己电脑上试用（不需要别人的服务器和密钥）
插件只连你填的地址，所以最省事的试法是在自己电脑上起一套后端，不需要模型密钥（用演示模式）。前端不用起。需要 Docker Desktop、Git、[uv](https://docs.astral.sh/uv/) 和 Python。

1. 拉最新 `main`，在仓库根目录复制环境文件并打开演示模式：`cp .env.example .env`，再往 `.env` 末尾加一行 `LLM_MODE=demo_fake`。本机 5432 端口被别的程序占用时，把 `.env` 里 `POSTGRES_PORT` 和 `DATABASE_URL` 的端口一起改成 5433。
2. `docker compose up -d db`
   （在仓库根目录。如果本机装了系统代理，访问本机地址时设 `NO_PROXY=127.0.0.1,localhost`，否则脚本登录可能返回 502。）
3. `cd backend`，然后依次：`uv sync`、`uv run bash scripts/prestart.sh`（迁移和内置场景模板）、`uv run python -m app.seed --fake-embeddings`（演示品牌和商品）。
4. 另开一个终端，在 `backend` 里：先 `mkdir -p app/frontend`（后端要求这个目录存在，它不进仓库，全新克隆的仓库里没有；前端不用起，空目录即可），再 `uv run fastapi run --port 8000`。
5. 回到仓库根目录，把要测的笔记网址交给脚本（可重复写多个 `--note-url`，网址里的查询串会被丢掉）：
   `python scripts/plugin_test_setup.py --note-url https://www.xiaohongshu.com/explore/<24 位笔记 id>`
   脚本会为每个网址生成并确认一篇测试文案、把网址绑定上去，再生成一个插件密钥，最后打印一整串**连接配置**。
6. 把这串粘贴到插件“连接设置”的第一栏，点“使用配置并授权”。然后在 Chrome 里打开那篇笔记，点“读取当前页面”和“发送到系统”。
7. 回到系统（或调 `GET /confirmed-copies/{id}/metrics`）能看到来源为 `extension` 的读数。

注意：
- 脚本里的文案是演示模式假模型写的，只用来承载网址，不要当作文案效果；这个库只用来试插件，不要用它录视频。
- 连接配置含密钥，只在终端显示一次，不要发到聊天、PR 或 Issue。要再试一遍，重新运行脚本即可（已绑定的网址会跳过，会生成新的密钥，旧密钥可继续用或在系统里作废）。
- 默认管理员账号来自 `.env` 的 `FIRST_SUPERUSER` 与 `FIRST_SUPERUSER_PASSWORD`，脚本自动读取。

## 测试
`node --test extensions/results-helper/test/parse.test.js`（解析、交叉核对和连接配置的单元测试，CI 的 `frontend-build` 里会跑；`test/fixture.html` 是页面结构副本）。后端的密钥与接口测试在 `backend/tests/api/routes/test_extension.py`。
