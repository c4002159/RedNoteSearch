# 演示视频脚本草稿（6 个场景）

依据 `docs/demo/B_DEMO_REVIEW.md`。**这是草稿：我没有在真实模型上走过，“屏幕上应该看到什么”按设计与契约写；A 跑通后请按实际屏幕改。** 措辞统一用“风险提示”“系统判定支持”“人工确认”，不说“合规通过”“已验证事实”“法务批准”“保证合规”。所有示例数据标“演示”。

## 场景 1：从品牌资料到可用文案
- 开场一句话：“资料先审核，审过的才会被用来写文案。”
- 点击顺序：知识库 → 上传资料 → 待审队列 → 审核通过 → 生成工作台 → 选品牌、商品、场景、风格 → 生成。
- 屏幕上应看到：资料状态由“待审核”变“已入库、可检索”；生成时显示阶段进度；结果页出现标题、正文、标签。
- 结束一句话：“没审核过的资料，不会进入检索。”

## 场景 2：每个事实都有出处
- 开场一句话：“文案里的每个产品事实，都能点开看到出处。”
- 点击顺序：结果页 → 事实证据面板 → 展开一条断言 → 看资料原文与版本。
- 屏幕上应看到：断言旁边是“系统判定支持”，原文片段高亮；没有依据的断言标为需要人工决定。
- 结束一句话：“系统判定支持只表示匹配，不等于事实正确；没依据的由人逐条决定。”

## 场景 3：风险提示与自动改写
- 开场一句话：“写出‘最好’‘第一’这类词，系统会提示风险。”
- 点击顺序：结果页 → 风险提示 → 点开一条看来源与条款 → 编辑 → 重新检查。
- 屏幕上应看到：提示标签是“风险提示”，带来源名与条款；编辑后产生新版本，检查重新运行。
- 结束一句话：“这是提醒人复核，不是结论。”

## 场景 4：客户自己维护规则
- 开场一句话：“规则不是写死的，客户自己可以改。”
- 点击顺序：风险提示规则 → 下载模板 → 导入规则（预览与合并）→ 导出规则 → 新建一条规则。
- 屏幕上应看到：导入预览有成功与错误行；规则带来源、条款、有效期。
- 结束一句话：“来源核实过的规则才标为正式依据，其余显示‘来源待核对’。”

## 场景 5：版本与导出
- 开场一句话：“每次改动都是新版本，随时可以回看和对比。”
- 点击顺序：任务与版本历史 → 打开任务 → 选两个版本对比 → 结果页 → 确认 → 导出。
- 屏幕上应看到：版本对比差异；确认后状态为“可复制（运营已确认）”；导出标题、正文、标签三段分开。
- 结束一句话：“运营确认表示文字已确认，不是外部审批。”

## 场景 6：怎么知道它好不好
- 开场一句话：“效果不靠感觉，靠固定版本的评测集。”
- 点击顺序：评测集 → 新建运行 → 评测运行与报告 → 看指标；爆款结构分析 → 添加样本 → 分析 → 转场景模板。
- 屏幕上应看到：指标有定义、没有综合分；品牌串味只说“被诱导时是否写出别家品牌词”。
- 结束一句话：“样本量小，只能说明链路可用，不能说明模型准确率。”

## 演示前检查
- 账号：品牌管理员与编辑者各一个；编辑者演示“看不到管理入口”。
- 演示用的规则：只用来源已人工复核的（S1、S2，复核完成后）；S3 到 S6 仍待核，不要当正式依据讲。
- 提前录屏备份；备一条模型慢或 503 的体面说法。
