# 演示视频脚本草稿（6 个场景）

依据 `docs/demo/B_DEMO_REVIEW.md`。**这是草稿：我没有在真实模型上走过，“屏幕上应该看到什么”按设计与契约写；A 跑通后请按实际屏幕改。** 措辞统一用“风险提示”“系统判定支持”“人工确认”，不说“合规通过”“已验证事实”“法务批准”“保证合规”。所有示例数据标“演示”。

## 哪些流程稳定、哪些必须用真实模型（2026-11-02 更新）

依据：我在本地演示库用 `LLM_MODE=demo_fake`（文字包含式假模型，每个版本的模型名都是 `demo-fake`）走过的流程，加上 A 在 `docs/HANDOFF.md` 第 9 节记录的真实模型验证。**假模型只用来走流程、看界面，不要录进给客户看的视频。**

| 流程 | 假模型下我实际看到的 | 录真实视频时 |
|---|---|---|
| 生成 → 结果页 | 任务能创建、生成、进入结果页，约 10 秒内完成 | 稳定，可由 A 直接录；A 记录真实模型生成约 24 秒，**预计耗时以 A 实测为准** |
| 编辑 → 保存为新版本 → 重新检查 | 保存后状态“已编辑待复检”；点重新检查后出现“正在重新检查…”，几秒后自动出现事实依据与风险提示（#89 合并后） | 稳定；重新检查依赖模型，耗时以 A 实测为准 |
| 确认可复制 → 复制到小红书（标题、正文、话题分开） | 有未判断断言或未处理“必须修改”提示时按钮禁用并说明原因；逐条处理后可确认，导出区写“系统判定支持 n 条，人工确认（非系统验证） n 条” | 稳定；这是最适合录的一段 |
| 版本历史与对比 | 能选两个版本对比 | 稳定 |
| 风险提示规则：下载模板、导入预览与合并、导出、新建 | 前端与后端都能走 | 稳定，不依赖模型；只用来源已人工复核的规则（S1、S2） |
| 知识库：上传、待审、审核通过 | 通过时要建索引，需要嵌入模型；演示库里已有已审核资料 | 通过时依赖嵌入模型，A 录 |
| **事实核查**（“系统判定支持”） | 假模型是文字包含式判断，**不能代表真实效果** | 必须真实模型，A 录 |
| **风险提示的模型判断部分** | 假模型这一步返回空；词表命中是代码判断，可以演示 | 词表命中稳定；语义判断必须真实模型，A 录 |
| **品牌串味测试（F14）** | 未用假模型跑过 | 必须真实模型；A 记录单样本约 9 到 16 秒 |
| **爆款结构分析（F13）** | 本地没有模型，分析窗口显示“没有可用模型”，没走过 | 必须真实模型；A 记录约 6 秒 |
| 评测：合规评测 | 不需要模型 | 稳定；生成评测、核查评测需要模型，且样本量小 |

**万一失败怎么圆**（不假装成功）：模型 503 或超时时，页面会显示“模型暂时不可用，任务没有丢，可以直接重试”，就照这句话讲，重试一次；还不行就切到提前录好的备份。检查长时间停在“正在重新检查…”时，不要重复点，等它走完或换备份。

## 场景脚本：左边是屏幕画面，右边是旁白（口语）

写法约定：画面只写我（B）在假模型下实际看过、或按 spec 和契约应有的内容；**标“以现场为准”的是必须用真实模型才有效果的片段，旁白不承诺具体结果，由 A 录的时候按屏幕上实际出现的内容讲**。旁白里没有任何数字承诺（耗时、准确率、条数都不讲死）。

### 场景 1：从品牌资料到可用文案

| 屏幕画面 | 旁白 |
|---|---|
| 知识库“资料列表与上传”，点“上传资料”，选文件，填标题和类型 | 先把品牌的资料放进来。资料是系统写文案的唯一依据。 |
| 切到“待审队列”，点一条“审核”，通过 | 放进来的资料要先过一道人工审核，审过的才算数。 |
| 资料列表里状态变成“已入库”“可检索”（建索引依赖嵌入模型，由 A 现场录，以现场为准） | 审核通过后，它才会被用来写文案、核对事实。没审的，系统不会碰。 |
| 生成工作台：选商品、场景，写一句创作要求，点“创建并开始生成” | 回到生成工作台，选好商品和场景，说一下想写什么。 |
| 阶段进度走完，点“查看结果” | 系统一边写，一边检查字数、事实和风险，写完就能看结果。耗时以现场为准。 |

### 场景 2：每个事实都有出处（需要真实模型，以现场为准）

| 屏幕画面 | 旁白 |
|---|---|
| 结果页右侧“事实依据”，看每条断言和它的状态 | 文案里提到的产品事实，系统会一条一条拿去资料里找出处。 |
| 展开一条标“系统判定支持”的断言，看来源资料、版本和原文片段（以现场为准） | 找到了，就给你看是哪份资料、哪个版本、哪一句。 |
| 找不到依据的断言显示“未找到证据”，旁边有“成立”“不成立”（具体哪几条以现场为准） | 找不到的，系统不替你做决定，交给人逐条判断。 |
| 点“成立”，弹窗里写判断依据，确认后标“人工确认（非系统验证）” | 人确认过的会清楚标出来，它是人的判断，不是系统验证出来的。 |

### 场景 3：风险提示与重新检查

| 屏幕画面 | 旁白 |
|---|---|
| 结果页“风险提示”，点开一条命中的提示，看命中的词、建议、来源（词表命中是代码判断，可以演示；模型判断的部分以现场为准） | 写到“最好”“第一”这类词，系统会提示风险，告诉你命中了什么、依据是哪条规则。 |
| 点“编辑”，改正文，“保存为新版本”；点“重新检查” | 你可以直接改字。改完是新的一版，老的还在，再检查一遍就行。 |
| 页面先显示“正在重新检查…”，随后自动出现新的事实依据和风险提示 | 检查是在后台跑的，跑完页面会自己更新。 |
| 对“必须修改”的提示点“标记为已处理”，写处理说明 | 必须修改的提示，得有人写清楚怎么处理的，才能往下走。 |
| 页面上“风险提示”下方的说明文字（“不是合规结论”） | 这些只是提醒，帮人复核，不是结论，也不能替代人的判断。 |

### 场景 4：客户自己维护规则

| 屏幕画面 | 旁白 |
|---|---|
| “风险提示规则”页，点“下载模板” | 规则不是写死的，客户自己能改。先下载一份模板。 |
| 点“导入”，选填好的文件，看预览（有成功的行，也有出错的行），再合并 | 填好导进来，先预览，哪一行有问题一目了然，确认没问题再合并。 |
| 点“导出”，再点“新建”，填来源、条款、有效期 | 也可以导出现有规则，或者单条新建。每条规则都要写来源和条款。 |
| 规则带“来源待核对”标记的那几条 | 来源还没核实的规则，页面会写“来源待核对”，不会当成正式依据。 |

### 场景 5：版本与导出

| 屏幕画面 | 旁白 |
|---|---|
| “任务与版本历史”，打开一个任务，看版本列表 | 每改一次就是一个新版本，历史都在。 |
| 选两个版本，点“对比” | 想知道改了什么，选两版一对比就看得到。 |
| 回到最新版本，所有断言和提示处理完，点“确认可复制” | 都处理完了，才能确认。 |
| “复制到小红书”：标题、正文、话题分开复制 | 标题、正文、话题分开复制，粘贴到发布页后，字数和话题请在发布页再确认一遍。 |
| 状态“可复制（运营已确认）”，页面写“系统判定支持 x 条，人工确认（非系统验证） y 条”（数字以现场为准） | 这里的“确认”是运营确认了这份文字，不是外部审批。 |

### 场景 6：怎么知道它好不好（需要真实模型，以现场为准）

| 屏幕画面 | 旁白 |
|---|---|
| “评测集”页，看固定版本的评测集 | 效果不靠感觉，靠固定版本的评测集来看。 |
| 新建运行，到“评测运行与报告”看指标和它们的定义（具体指标和数值以现场为准） | 每个指标都有定义，没有一个笼统的总分。 |
| 品牌串味测试：看结果卡（以现场为准） | 串味测试看的是：被引导的时候，会不会写出别家品牌的词。 |
| 爆款结构分析：添加样本，点“分析结构”，看结构，必要时“转为场景模板”（以现场为准） | 也可以拿一篇有授权的文案，提取它的结构，再变成自己的场景模板。 |
| 回到评测页面 | 样本量还小，现在只能说明这条链路是通的，说明不了模型到底准不准。 |

## 演示前检查
- 账号：品牌管理员与编辑者各一个；编辑者演示“看不到管理入口”。
- 演示用的规则：来源只用 S1、S2（Ray 逐条复核过，已登记）；S3 到 S6 只登记了人工复核、范围未逐条记录，讲的时候不要说成逐条核对过，也不要写入 `source_clause`。
- 视频里不出现 `demo_fake` 的结果（版本头会写“模型 demo-fake”）。
- 提前录屏备份；备一条模型慢或 503 的体面说法（页面会写“模型暂时不可用，任务没有丢，可以直接重试”，照着讲；不要假装成功）。
