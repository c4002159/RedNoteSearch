# ADR-005 复制格式中的标签：标题、正文、标签分开复制

状态：已修订（2026-10-31）。取代 2026-10-30 的“标签写作纯文本 `#标签`，放在正文末尾”。依据：团队在发布页的实测结果。

## 实测结果（团队通过浏览器助手测得；我没有亲自复现）
| 动作 | 结果 |
|---|---|
| 把 `粘贴测试 #Softcore #逐帧动画 结束` 用 Ctrl+V 粘贴进正文框 | **(a) 全部是普通文字**：没有弹窗，没有话题选择，页面里没有新增话题节点 |
| 用键盘逐字输入 `#词` 再按空格 | 若该词命中官方话题库，会自动变成蓝色话题；**粘贴不会**走这套处理 |
| 点“# 话题”按钮选一个话题 | 显示为蓝色可点击文字；结构是 `<span class="tiptap-topic">#话题名<span class="content-hide">[话题]#</span></span>`，真实标签名后面跟着肉眼不可见的 `[话题]#` |
| 隐藏后缀的影响 | 它不是 `display:none`（样式为 `width:1px; overflow:hidden`），所以手选复制或读 `innerText` 都会带出 `[话题]#` |
| 话题数量 | 最多 10 个；第 11 个会弹出“最多添加10个话题”提示，但编辑器仍会插入；强制拦截应在发布时（**未验证**） |

## 决定
1. **标题、正文、标签三者分开复制**，不再把标签拼进一段正文文本。界面提供三个复制按钮：“复制标题”“复制正文”“复制标签”。
2. 标签复制出来是纯文本 `#标签1 #标签2`（单个空格分隔），界面旁边写明操作：**粘贴不会变成话题**；要在发布页用键盘输入 `#` 加话题名再按空格，或点“# 话题”按钮选择。标签列表同时显示“已选 N / 10”。
3. 我们自己生成文本，所以不需要处理 `[话题]#` 后缀；但**导入用户从发布页复制的样本时**（爆款结构分析 F13），要把 `[话题]#` 去掉，否则样本里会带着隐藏的垃圾文字。
4. 标签数量 ≤10，作为约束检查；标签的可见字符还要算进正文 1000 的预算（见 ADR-004）。
5. 契约：`export?format=xhs_text` 改为 `xhs_parts`，返回三个独立字段加计数信息；原 `xhs_text`（单段文本）不再提供。

## 影响
- `docs/API_CONTRACT.md` 的导出一节、`docs/TEST_CASES.csv` 的 TC-027、TC-042，以及新增的 TC-050（标签数量）、TC-051（导入样本去除 `[话题]#`）。
- 前端复制交互按“三个按钮”设计（B 的设计稿需要体现）。

## 仍待测
- 点击“发布”时话题超过 10 个、字数超限是否真的被拦截（没有真的发布测试笔记）。
- 命中官方话题库时，键盘输入转话题的具体条件。这影响提示文案，不影响数据结构。
