# ADR-011 人在回路：没有系统依据的断言必须由人逐条决定

状态：已确认并已实现（2026-11-01，PR #32）。补充技术文档 2.3 “确认语义”。

## 背景
系统会把文案里的断言和已审核资料或任务资料做核对，但核对不到、或只能由模型判断的断言，不能被悄悄放行，也不能让系统自己宣布“成立”。

## 决定
1. 证据的“系统判定”（`status`）由代码核对得出：引用的资料存在、原文真的出现在里面，才可能是 `system_supported`；只信模型不算。
2. 系统判定不是 `system_supported` 的断言，必须由人逐条给出“成立 / 不成立”（`POST /claim-evidence/{id}/confirm`，备注建议填写）。人的决定与系统判定分开存放，**不改写系统的 `status`**。
3. 确认可复制（`ready_to_copy`）要求：各检查已针对当前文字运行、没有断言未判断或被判不成立、没有未处理的“必须修改”风险提示、约束已通过、是最新版本。不满足时服务端返回 `INVALID_STATE`，`details.reasons[]` 给出可读原因；界面只显示这些文字。
4. 人工确认过的断言，在界面和导出里标注“人工确认（非系统验证）”；Markdown 末尾附“人工核对记录”。`ready_to_copy` 只表示运营确认了文字，不表示合规，也不表示事实已被验证。
5. 措辞红线不变：不出现“合规通过”“已验证事实”“法务批准”“保证合规”（CI `forbidden-wording` 检查）。

## 影响
- 演示里“没有依据”的说法不会被系统自动放行；运营要为每一条负责，审计里可回查。
- 备注是否必填：后端不强制，界面设计保持“建议填写”。
