# ADR-004 标题与正文字数口径：与小红书发布页一致

状态：已修订（2026-10-31）。取代 2026-10-30 的“按 Unicode 字素簇计数”。依据：团队在小红书图文发布页的实测结果（见下）。部分边界情形仍待测。

## 修订原因
2026-10-30 的决定是按字素簇计数，当时只有发布页截图上的上限（标题 20、正文 1000），没有计数规则。随后的实测表明**发布页的真实规则与字素簇不同**：标题按全角 1、半角 0.5 加权，正文按 UTF-16 单位计数且不计换行。约束检查的目的是“发布时不被拦住”，所以必须与发布页一致，而不是与用户直觉一致。

## 实测结果（团队通过浏览器助手在发布页测得；我没有亲自复现）
| 项 | 规则 | 备注 |
|---|---|---|
| 标题上限 | 20 | 计数器显示 `0 / 20` |
| 标题计数 | 中文全角字符计 1，英文字母、数字等半角字符计 0.5 | 所以纯中文最多 20 字，纯英文或数字最多 40 个字符 |
| 标题超限 | 输入时不截断，数字变红 | 真正拦截应在点击“发布”时，**这一点没有验证** |
| 正文上限 | 1000 | 计数器显示 `0/1000` |
| 正文计数 | 逐字符 1:1，不分全角半角；空格、英文字母、`#` 各计 1 | 与标题的加权不同 |
| 正文换行 | `\n` 不计数 | 插入换行前后数字不变 |
| 正文 emoji | 每个 emoji 计 2 | 与 JavaScript 的 UTF-16 `.length` 一致 |
| 话题文字 | 可见部分计入正文字数，隐藏后缀 `[话题]#` 不计入 | 见 ADR-005 |
| 话题数量 | 最多 10 个 | 超过时弹出“最多添加10个话题”提示，但编辑器仍会插入第 11 个；强制拦截应在发布时，**没有验证** |
| 图片 | 18 | 计数器 `1/18`；本项目不生成图片 |

## 决定
1. **标题**：`title_weight(text) = Σ（每个字符：ASCII 可打印字符 U+0020 至 U+007E 计 0.5，其余字符计 1）`，约束 `title_weight ≤ 20`。按 Unicode 码点遍历（Python 的 `for ch in text`，JavaScript 的 `Array.from(text)`）。
2. **正文**：`body_units(text) = 去掉全部 \n 之后的 UTF-16 码元数`（Python：`len(text.replace("\n", "").encode("utf-16-le")) // 2`；JavaScript：`text.replace(/\n/g, "").length`），约束 `body_units ≤ 1000`。
3. **标签**：数量 ≤10（约束检查）。标签的可见文字（`#` 加标签名，标签之间的空格）要算进正文预算，所以合并约束为：`body_units + Σ（1 + 标签名的 UTF-16 码元数 + 1）≤ 1000`。这是保守估算，空格怎么计待发布页验证。
4. 计数函数**只写一处**：后端 `app/domain/constraints/length.py`（B 负责）是权威；前端提示用上述同一规则的镜像实现，结果以后端判定为准。两边用同一组边界用例互相核对（TC-016、TC-049、TC-F05）。
5. “按字素簇计数”的方案废弃。regex 库的 `\X` 已验证可用，但不再用于字数约束，其他需要字素簇的地方仍可使用。

## 仍待测（在发布页做，结果补进本文件）
- 标题里的全角标点（如 `，`）、中文括号、空格、emoji 各计多少；本决定把“ASCII 可打印字符以外一律计 1”当作假设。
- 点击“发布”时，标题超限、正文超限、话题超过 10 个是否真的被拦截，以及提示文案。
- 标签之间的空格、换行在正文里的实际计数。

## 影响
- 约束检查（F6）、前端字数提示、契约、测试用例 TC-016、TC-049、TC-F05 都按本决定修订。
- 约束放在**发布前**拦截，所以边界情形宁严勿松：不确定时按更长的一侧算。
