## 跑法与结论（B 的助手，2026-11-01，`LLM_MODE=demo_fake`，云端环境，演示库）
- 环境：PostgreSQL＋pgvector，`LLM_MODE=demo_fake`。**没有嵌入密钥，所以我在本地启动脚本里把 `get_embedder` 换成了 `FakeEmbeddingProvider`（只在我本机，没提交）**；演示库的知识库向量本来就是 `--fake-embeddings` 灌的。假模型结果没有真实意义，不评价文案质量。
- 页面问题（我自己的文件，已提 #85）：`last_error` 原样英文；结果页计数行显示原始字段名。
- 列给 A 的后端问题：
  1. **`LLM_MODE=demo_fake` 在没有 `DASHSCOPE_API_KEY` 时仍然生成失败**：`POST /tasks/{id}/generate` 返回 202，后台检索需要嵌入，抛 `ModelUnavailableError: Embedding model is not configured`，任务 `last_error=model_unavailable`、状态回到 `queued`。期望：demo_fake 也替换嵌入器（或文档写明还要配嵌入密钥）。HANDOFF 第 103 行只写了替换三个入口。
  2. **重新检查后版本为 `needs_human_review`，但没有任何断言和风险提示**：事实依据 0 条、风险提示 0 条、约束通过。契约第 300 行说“有未得到支持且无人确认的断言，或有未处理的 block 级风险提示”才是 `needs_human_review`，否则 `checks_completed`。期望 `checks_completed`；实际用户无法确认。请 A 判断是假模型特有还是后端判定问题。
- 对比页没有字数、约束、风险提示的变化（checklist 期望较高）；请 A 或我判断是否需要补。
- 页脚仍是“Full Stack FastAPI Template - 2026”，侧栏 “Appearance” 仍是英文（A 已知，另一个 agent 在改）。
- 没跑到：A3、A4、B1、B3、B4、C3、C4、D3、E1、G1、G2。C3、C4、E1 需要有“没有系统依据的断言”和风险提示规则，假模型两者都没有；演示库里规则库是空的。
